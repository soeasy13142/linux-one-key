# ClamAV 可选 clamd 守护进程安装方案

## 背景

当前 `scripts/security/clamav.sh` 仅配置 freshclam（病毒库更新）+ 按需扫描（cron 定时），明确不启用 clamd 守护进程（对服务器太重）。PRD §2.13.2 指出"大内存服务器可选择性启用 clamd"。

需要在现有 ClamAV 模块基础上增加一组可选函数，允许用户在 wizard 中选择是否安装并启动 clamd 守护进程，实现实时文件监控保护。

## 目标

1. 新增 4 个内部函数：`_install_clamd`、`_enable_clamd`、`_start_clamd`、`_disable_clamd`
2. 在 `run_clamav_wizard()` 中增加可选步骤（在 freshclam cron 之后、扫描 cron 之前）
3. 新增约 10 条 i18n 键（中/英）
4. 在 `check_clamav_status()` 中增加 clamd 状态输出
5. 在 report.sh ClamAV 段落增加 clamd 状态行
6. 新增约 5 个 Bats 测试用例
7. ShellCheck + Bats 验证

## 执行步骤

### Step 1: clamav.sh — 新增 4 个内部函数（~80 行）

#### `_install_clamd()`

在 `_install_clamav()` 之后，单独安装 clamd 依赖包。逻辑：

```
_install_clamd() {
    log_step "${MSG_CLAMAV_CLAMD_INSTALL}"

    case "${DETECTED_OS:-}" in
        ubuntu|debian)
            apt-get install -y clamav-daemon >> "${LOG_FILE}" 2>&1 || {
                log_error "${MSG_CLAMAV_CLAMD_INSTALL} failed"
                return 1
            }
            ;;
        centos|rhel|rocky|almalinux|fedora)
            # RHEL 系列: clamd 是 clamav-server 包的一部分
            yum/dnf install -y clamav-server >> "${LOG_FILE}" 2>&1 || {
                log_error "${MSG_CLAMAV_CLAMD_INSTALL} failed"
                return 1
            }
            ;;
        *)
            log_error "${MSG_CLAMAV_UNSUPPORTED_OS}"
            return 1
            ;;
    esac

    log_success "${MSG_CLAMAV_CLAMD_INSTALL_DONE}"
}
```

设计要点：
- **已在 `_install_clamav()` 中安装过 clamav-daemon 的用户**：Debian 系在 `_install_clamav()` 中已安装 `clamav-daemon`，但立即被 `systemctl stop/disable`。`_install_clamd()` 不需要重复安装包，直接返回 0 即可。需要通过 `dpkg -l clamav-daemon` 或 `rpm -q clamav-server` 检查是否已安装。
- 幂等性：如果包已安装则 `apt-get install` 返回 0，安全。
- location：插入在 `_install_clamav()` 之后、`_configure_freshclam()` 之前（源代码顺序）。

#### `_enable_clamd()`

配置 `clamd.conf`。`CLAMAVD_CONF` 常量已定义（第 25 行），当前值为 `${CLAMAV_CONF_DIR}/clamd.conf`。

```
_enable_clamd() {
    log_step "${MSG_CLAMAV_CLAMD_CONFIGURE}"

    mkdir -p "${CLAMAV_CONF_DIR}" "${CLAMAV_LOG_DIR}"

    if [[ -f "${CLAMAVD_CONF}" ]]; then
        backup_file "${CLAMAVD_CONF}"
    fi

    local tmp_conf
    tmp_conf=$(mktemp)

    cat > "${tmp_conf}" <<CLAMDEOF
# clamd.conf - Generated by linux-one-key
# ClamAV daemon configuration for real-time protection

# Logging
LogFile ${CLAMAV_LOG_DIR}/clamd.log
LogTime yes
LogVerbose no

# Listen
LocalSocket /var/run/clamav/clamd.sock
# TCP socket (optional, commented out by default)
#TCPSocket 3310
#TCPAddr 127.0.0.1

# Performance
MaxThreads 4
MaxConnectionQueueLength 15
StreamMaxLength 100M

# Scanning
ScanOLE2 yes
ScanPDF yes
ScanHTML yes
ScanArchive yes
ArchiveMaxRecursion 5
ArchiveMaxFiles 15000

# Exclude
ExcludePath ^/proc/
ExcludePath ^/sys/
CLAMDEOF

    mv "${tmp_conf}" "${CLAMAVD_CONF}"
    log_success "${MSG_CLAMAV_CLAMD_CONFIGURE_DONE}"
}
```

设计要点：
- 使用 `mktemp` + `mv` 原子写入模式（与 `_configure_freshclam` 一致）
- 模板提供合理的默认值（MaxThreads=4, MaxConnectionQueueLength=15）
- 使用 `backup_file` 备份已有配置

#### `_start_clamd()`

```
_start_clamd() {
    log_step "${MSG_CLAMAV_CLAMD_ENABLE}"

    if command -v systemctl &>/dev/null; then
        systemctl unmask clamav-daemon >> "${LOG_FILE}" 2>&1 || true
        systemctl enable clamav-daemon >> "${LOG_FILE}" 2>&1 || {
            log_error "${MSG_CLAMAV_CLAMD_ENABLE} failed (enable)"
            return 1
        }
        systemctl start clamav-daemon >> "${LOG_FILE}" 2>&1 || {
            log_error "${MSG_CLAMAV_CLAMD_ENABLE} failed (start)"
            return 1
        }
    else
        log_error "systemctl not available"
        return 1
    fi

    log_success "${MSG_CLAMAV_CLAMD_ENABLE_DONE}"
}
```

设计要点：
- Debian 上 `_install_clamav()` 已执行过 `systemctl stop/disable/mask`，所以需要使用 `systemctl unmask` 恢复
- 幂等性：systemctl enable/start 重复运行安全

#### `_disable_clamd()`

```
_disable_clamd() {
    log_step "${MSG_CLAMAV_CLAMD_DISABLE}"

    if command -v systemctl &>/dev/null; then
        systemctl stop clamav-daemon >> "${LOG_FILE}" 2>&1 || true
        systemctl disable clamav-daemon >> "${LOG_FILE}" 2>&1 || true
    fi

    # 保留配置文件但改名（便于恢复）
    if [[ -f "${CLAMAVD_CONF}" ]]; then
        mv "${CLAMAVD_CONF}" "${CLAMAVD_CONF}.disabled.${TIMESTAMP}" 2>/dev/null || true
    fi

    log_success "${MSG_CLAMAV_CLAMD_DISABLE_DONE}"
}
```

设计要点：
- 设计为清理函数，用于卸载场景
- 保留配置文件备份（改名而非删除），便于恢复

### Step 2: clamav.sh — Wizard 集成

在 `run_clamav_wizard()` 的 Step 3 (freshclam cron) 和 Step 4 (run freshclam now) 之间插入新步骤。重新编号：

- Step 1: `_install_clamav`
- Step 2: `_configure_freshclam`
- Step 3: `_setup_freshclam_cron`
- **Step 3.5 (新增): clamd 可选提示**
  ```
  # ── Step 3.5: Optional clamd daemon ──
  if [[ ${wizard_rc} -eq 0 ]]; then
      if confirm "${MSG_CLAMAV_CLAMD_PROMPT}" "n"; then
          _install_clamd || wizard_rc=1
          if [[ ${wizard_rc} -eq 0 ]]; then
              _enable_clamd || wizard_rc=1
          fi
          if [[ ${wizard_rc} -eq 0 ]]; then
              _start_clamd || wizard_rc=1
          fi
      else
          log_info "${MSG_CLAMAV_CLAMD_SKIPPED}"
      fi
  fi
  ```
- Step 4: `_run_freshclam_now`
- Step 5: `_setup_scan_cron`

默认回答 `"n"`（跳过），与 ClamAV 一贯的轻量理念一致。

### Step 3: clamav.sh — `check_clamav_status()` 增加 clamd 状态

在 `check_clamav_status()` 末尾增加：

```bash
# Check clamd status
local clamd_enabled="no"
if command -v systemctl &>/dev/null; then
    if systemctl is-enabled clamav-daemon &>/dev/null 2>&1; then
        clamd_enabled="yes"
    fi
fi

echo "clamav_clamd_enabled=${clamd_enabled}"
```

## 风险与注意事项

1. **Debian 系包已安装问题**：`_install_clamav()` 已安装 `clamav-daemon`，`_install_clamd()` 需要检测到已安装后跳过（幂等）
2. **systemd mask 恢复**：`_install_clamav()` 对 Debian 执行了 `systemctl mask clamav-daemon`，`_start_clamd()` 必须先 `systemctl unmask`
3. **RHEL 系包名差异**：RHEL 系使用 `clamav-server` 而非 `clamav-daemon`，需要确认实际包名（CentOS 7: `clamav-server`, CentOS 8+: `clamav` 可能已含）
4. **大内存提示准确性**：clamd 常驻内存约 300-500MB，提示文案需要与实际一致
5. **已有备份冲突**：`_enable_clamd()` 的 `backup_file` 调用需要确保与 `utils.sh` 一致
